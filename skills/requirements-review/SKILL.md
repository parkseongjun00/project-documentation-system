# 문서 기반 질문 검토

사용자가 지금 판단하려는 질문에서 시작한다. 관련 근거를 읽고 답에 따라 결과물이 달라지는 쟁점을 함께 좁힌다. 사용자가 질문의 순서, 검토 범위, 진행 속도를 정한다.

## 1. 현재 질문과 근거 확인

- 사용자의 질문과 이번 검토에서 결정하려는 것을 짧게 정리한다. 질문의 뜻이 분명하면 바로 근거를 확인한다.
- 프로젝트의 문서 지도나 사용자가 준 경로에서 현재 질문과 관련된 문서만 읽는다. `ProjectSpec.md`에서 요구·완료 기준·제약을, `Systems.md`에서 기능 범위를, `DevPlan.md`에서 순서·확인 기준을 찾는다. 같은 역할의 다른 문서도 사용할 수 있다.
- 과제 원문이나 제공 자료가 있으면 관련 요구를 직접 대조한다. 사용자가 작성한 명세와 원문 사이에 차이가 있으면 해당 구절과 판단에 미치는 영향을 제시한다.
- 현재 동작이 쟁점이면 관련 코드나 실제 검증 결과도 확인한다. 구현에서 관찰한 사실과 채택할 기준은 구분한다.
- 확인 가능한 사실은 도구와 자료에서 먼저 찾는다. 접근할 수 없거나 자료가 없으면 미확인 범위와 판단에 미치는 영향을 밝힌다.

## 2. 판단이 달라지는 쟁점 선택

- 자료에 답이 있는 항목은 근거와 함께 답한다.
- 서로 다른 요구 해석, 문서 간 충돌, 빠진 결정, 임시 가정 중 이번 판단에 영향을 주는 것을 찾는다.
- 필수 동작, 완료 기준, 해결 방식, 제출 범위 또는 다음 작업이 달라지는 질문을 먼저 고른다. 선행 결정에 의존하는 질문은 그 결정 후 다시 살핀다.
- 제한 시간이나 남은 시간이 주어졌다면 질문의 중요도와 확인 비용에 반영한다. 사용자가 직접 정한 질문 우선순위를 따른다.

## 3. 질문과 선택지 제시

필요한 질문을 짧게 제시한다. 서로 독립적인 질문은 함께 물을 수 있고, 사용자가 한 번에 하나씩 진행하기를 원하면 그 방식에 맞춘다.

| 질문 | 근거와 미확인 사항 | 답에 따라 달라지는 것 |
| --- | --- | --- |

질문이 하나이고 짧으면 문단으로 쓴다. 판단에 도움이 되는 선택지가 있으면 예상 결과와 장단점을 덧붙인다. 추천안을 제시할 때는 원문 근거, 가정, 추천 이유를 구분한다. 자료에 없는 현업 요구는 확인할 질문이나 임시 가정으로 표시한다. 사용자의 답과 선택을 확인한 뒤 그에 의존하는 판단을 진행한다.

## 4. 답변 이후와 마무리

- 답을 받으면 현재 결론과 남은 쟁점을 갱신한다. 새 답이 이번 작업에 영향을 주는 질문을 추가로 여는지 살핀다.
- 사용자가 충분하다고 판단하거나 보류·종료를 요청하면 그 지점에서 마무리한다. 다음 작업과 확인 방법을 정할 수 있으면 진행할 근거와 남은 가정을 짧게 제시한다.
- 마무리에는 결정한 내용, 근거, 남은 가정이나 미확인 사항, 다음 작업에 미치는 영향을 필요한 만큼 남긴다.
- 문서 반영까지 요청받았으면 문제·규칙은 명세에, 기능 범위는 기능 목록에, 순서·확인 기준은 계획에, 중요한 결정 이유는 결정 기록에 반영한다. 변경은 사용자가 요청하거나 이미 승인한 범위에서 진행한다.
