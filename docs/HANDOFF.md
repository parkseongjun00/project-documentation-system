## 0. 일러두기

- **목적과 범위**
	- 여러 세션이 공유할 현재 작업 요약이다. 확정된 기준·결정과 그 원본 중 이번 작업의 핵심만 간결하게 발췌하며, 상세 내용은 원본으로 연결한다.
	- 인계 시 기존 결정과 근거를 확인하고 변경 사유가 없는 한 재논의하지 않는다. 신규 설계 판단이 이번 라운드의 목적이면 미확정 안건도 상태를 구분해 담을 수 있다.
- **갱신과 보존**
	- 매 라운드 작업별 본문을 교체한다. 확정 규칙은 기준 문서, 주요 결정은 [DevNotes](DevNotes/README.md)에 보존하고 보류 과제는 [Backlog의 등록 조건](Backlog.md)에 따라 처리한다.
	- 본문·특정 절을 영구 근거로 참조하지 않는다. 버전·수정일·문서 내부 변경 이력은 두지 않고 과거 본문은 Git 이력으로 확인한다.
- **구조와 작성**
	- 제목·일러두기·기존 H2/H3 목차·작성 안내를 유지한다. 사용자의 명시적 요청 없이는 고정 구조를 수정·삭제하지 않으며, 새 분류가 필요할 때 해당 H2 아래 H3를 추가할 수 있다.
	- 관련 문서는 표 행 하나 또는 불릿 하나에 한 문서와 확인 목적 한 문장을 적는다.
- **승인과 세션 관리**
	- 문서 변경·구현·검증·commit·push는 각각 명시적으로 승인된 범위에서만 진행한다.
	- 병행 세션은 각자 [논의 초안](DiscussionDraft.md)을 관리하고 통합을 맡은 세션이 공용 HANDOFF를 갱신한다.
