# 문서 체계

---

## 0. 일러두기

이 문서는 문서별 역할, 편집 방식, 이관 조건을 정한다. 프로젝트 자체의 문제와 목표는 [프로젝트 명세](ProjectSpec.md)에서 관리한다.

---

## 1. 문서별 역할

| 문서 | 기록하는 내용 | 갱신 방식 |
|---|---|---|
| [ProjectSpec.md](ProjectSpec.md) | 문제와 목표, 해결 방향, 사용자 흐름, 동작 규칙, 제약 | 현재 합의에 맞춰 갱신하고 미정 사항을 표시 |
| [Systems.md](Systems.md) | 구현 범위에 들어가는 시스템·기능 | 범위 합의에 맞춰 갱신하고 상세 규칙을 참조 |

| [WritingGuide.md](WritingGuide.md) | 공통 문체, 서식, 출처 표기 | 반복되는 작성 관례가 바뀔 때 갱신 |

## 2. 정보가 이동하는 조건

1. 설계 규칙이나 구현 범위가 확정되면 각각 프로젝트 명세와 기능 목록을 갱신한다. 작업 순서가 달라지면 개발 계획을 갱신한다.
2. 다시 참고할 판단이나 구현 결정은 개발 노트에 사유와 함께 남긴다. 조사 중 실패 경로와 확인 조건은 트러블슈팅 기록에 보존한다.
3. 사용자가 다시 다루기로 정한 과제는 백로그에 등록한다. 미정 아이디어와 남은 검증은 해당 문서나 작업 요약에 남긴다.
4. 다음 작업에 필요한 범위와 상태는 인수인계에 요약한다. 오래 참조할 내용은 주제에 맞는 보존 문서에 두고 링크한다.
5. 상세 설명은 주로 관리하는 문서 한 곳에 둔다. 다른 문서에서는 해당 절을 연결하고 그 문서에 필요한 만큼 요약한다.

---

## 3. 합의와 검증

- 기준 문서는 합의된 동작을 기록한다. 구현과 검증은 실제 관찰한 동작의 근거다.
- 차이가 확인되면 기준, 실제 동작, 영향 범위를 제시해 기준 유지·변경·판단 보류 중 처리 방향을 정한다. 이미 합의한 변경은 승인 범위 안에서 반영한다.
- 미구현, 후순위 계획, 과거 판단은 각 기록의 시점과 역할에 따라 해석한다.
- 제안, 사용자 결정, 확인 결과, 미확인 사항을 문맥에 맞게 표시한다.
