## 0. 일러두기

- **목적과 범위**
	- 한 세션이 가장 최근 요청 하나의 논의·검토·선택지·제안·구현 초안·작업 메모를 정리하는 비영구 문서다. 대화만으로 읽기 어렵거나 사용자가 정리된 문서를 요청했을 때 사용한다.
	- 확정 사항·제안·작업 결과·미확인 사항을 구분한다. 초안을 사용하는 요청의 미확정 계획은 여기서 먼저 검토받고, HANDOFF나 DevNotes에 확정 내용처럼 쓰지 않는다.
- **갱신과 보존**
	- 새 요청에서는 1장 이후의 작업별 본문을 교체한다. 버전·수정일·문서 내부 변경 이력은 두지 않는다. 버전 관리에 포함한 경우 과거 본문은 Git 이력으로 확인한다.
	- 확정 후 기준·범위·순서는 해당 기준 문서에, 주요 결정은 [DevNotes](DevNotes/README.md)에, 인수인계할 작업은 [HANDOFF](HANDOFF.md)에 반영한다. 백로그 이관은 [등록 규칙](Backlog.md)을 따른다.
- **구조와 작성**
	- 제목·일러두기·기존 H2/H3 목차·작성 안내를 유지한다. 사용자의 명시적 요청 없이는 고정 구조를 수정·삭제하지 않으며, 새 분류가 필요할 때 해당 H2 아래 H3를 추가할 수 있다.
	- 관련 문서는 불릿 하나에 한 문서와 확인 목적 한 문장을 적는다. 필요한 정보만 간결하게 작성한다.
	- 작업 전에는 관련 기준 문서와 현재 코드·자산을 다시 확인한다.
- **세션 소유와 참조**
	- 지정된 경로가 있으면 해당 초안을 사용한다. 새 병행 초안은 이 양식을 복사해 세션과 주제를 구분하는 고유 이름을 쓰고, 작업 맥락에 소유 세션과 요청을 적는다.
	- 담당 세션만 읽고 갱신하며 담당 변경은 인계를 명시한다. 공통 기준에 영향을 주는 변경은 관련 세션과 조율한다.
	- 다른 세션은 HANDOFF와 보존 문서에서 공통 정보를 확인한다. 다른 문서에서 이 초안의 본문·특정 절을 참조하거나 읽도록 안내하지 않으며, 역할 안내에 파일명을 적는 것은 허용한다.

### 2.5 검증 기준

> **작성 안내**
>
> 이번 작업이 대응하는 요구와 과제 원문·기준 문서의 해당 위치를 적고, 요구별로 확인할 입력이나 조건, 확인 방법과 기대 결과를 정리한다. 단독 시연이 어려운 준비 작업은 지금 확인할 산출물과 이후 어느 작업에서 어떤 방법으로 동작을 확인할지도 적는다.
>
> 작업 중에는 관련 요구를, 최종 검토에서는 전체 필수 요구를 과제 원문과 대조한다. 과제 원문이 없는 작업은 사용자 요청과 기준 문서를 대조 기준으로 삼고, 원문에 접근하지 못했다면 그 범위를 미확인으로 남긴다. 실행하거나 대조해서 얻은 결과는 3.3 검증 결과에 기록한다.

### 3.2 사용자 확인

> **작성 안내**
>
> 다음 작업을 맡기기 전에 사용자가 확인한다.
>
> - **동작** - 대표 입력이나 원본 자료를 확인했을 때 기대한 결과가 나왔는가?
> - **이해** - 입력이나 근거에서 결과가 어떻게 나왔는지 내 말로 설명할 수 있는가?
> - **구조** - 바뀐 부분이 맡은 역할은 분명하고, 이번 요구에 필요한 만큼 단순한가?

### 3.3 검증 결과

> **작성 안내**
>
> 합의한 멈춤 지점에 도달하면 AI가 대응한 요구별로 다음 항목을 정리한다. 작업 중에는 관련 요구를, 최종 검토에서는 전체 필수 요구를 과제 원문과 대조하고 결과를 남긴다. 대조 기준과 접근하지 못한 자료는 2.5 검증 기준에 따른다.
>
> - **요구와 근거 위치** - 확인한 요구와 원문 위치, 대응하는 코드·문서·자료 및 검증 기록의 위치를 적는다.
> - **먼저 볼 위치** - 핵심 변경을 확인할 파일, 함수, 문서나 자료의 위치를 적는다.
> - **다시 확인하는 방법** - 사용자가 같은 동작이나 결과를 확인할 수 있도록 입력과 실행 또는 대조 방법을 적는다.
> - **실제 확인 결과** - 실행 또는 대조에 사용한 조건과 실제 결과를 적고, 요구와 기대 결과의 충족 여부를 밝힌다.
> - **미충족·미확인 사항** - 기대 결과를 만족하지 못한 사항과 확인하지 못한 사항을 구분하고, 해당 범위와 사유를 적는다.
