# 프로젝트 명세

---

## 0. 일러두기

이 문서는 풀려는 문제와 목표, 해결 방향, 동작 규칙과 제약의 기준이다. 확정된 내용과 결정이 필요한 사항을 구분해서 적는다.

---

## 1. 문제와 목표

- 프로젝트가 여러 세션과 작업 단계를 거치면 현재 기준, 기능 범위, 이전 결정, 미확인 사항이 여러 곳에 흩어져 다음 세션이 작업 맥락을 다시 모아야 한다.
- 게임 프로젝트에서 사용한 문서 체계를 여러 도메인에 적용할 수 있도록 정리한다.
- 사용자가 제공한 설명과 자료를 근거로 실질적인 문서 초안을 작성하고, 결정이 필요한 부분을 확인할 수 있게 한다.

---

## 2. 해결 방향

- 프로젝트 명세, 기능 범위, 작업 순서, 결정 이력, 인수인계가 각각 답하는 질문을 정한다.
- 문서별 일러두기와 기본 목차를 제공한다. 본문에는 해당 프로젝트의 사실과 합의를 채운다.
- 여러 작업을 병행할 때는 세션별 논의 초안을 사용하고, 확정된 내용을 공용 기준이나 보존 기록으로 옮긴다.

---

## 3. 동작 규칙과 제약

- 기존 프로젝트에서는 현재 문서와 도구를 먼저 살펴보고 역할에 대응시킨다. 예를 들어 이슈 트래커가 보류 과제를 관리하고 있다면 해당 위치를 백로그로 연결할 수 있다.
- 주요 결정이 바뀌면 현재 기준과 관련 범위 문서를 갱신한다. 결정 당시의 사유와 검증은 기록에 보존한다.
- 세션은 배정받거나 생성한 초안의 경로를 작업 중 유지한다. 다른 세션의 초안으로 결과를 옮기려면 해당 세션과 조율한다.
- 저장소가 공개이면 그 범위에서 공유할 수 있는 내용으로 초안을 작성한다. 민감한 자료를 다루는 세션에는 별도의 비공개 위치를 사용한다.
