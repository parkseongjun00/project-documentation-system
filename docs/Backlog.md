# 재검토 후보 백로그

---

## 0. 일러두기

- **목적과 등록**
	- 사용자가 다시 다룰 일로 정한 기획·기술 과제를 보존한다.
	- 신규 등록·재등록·범위 확대는 백로그라는 보존 위치를 명시한 사용자 요청 또는 등록안에 대한 명시적 동의가 있을 때만 한다. AI 제안은 대화에서 먼저 검토한다.
	- 아이디어·개발 방향·어딘가 기록하자는 요청·문서 이관·편집 승인은 백로그 등록 승인이 아니다. 기존 개발 계획·남은 검증을 자동 등록하거나 과거 제외 항목을 임의로 되살리지 않는다.
- **번호와 참조**
	- 미결 과제는 1장의 H3로 나누고 표시 번호를 문서 순서대로 갱신한다. 상태는 [보류]·[착수]로 표시한다.
	- 참조에는 번호·상태와 무관한 고정 앵커와 과제명을 사용한다.
- **처리와 보존**
	- 실제 관리한 과제의 완료·철회 결과는 별도 H2의 처리 표에 제목·상태·처리일·짧은 결과와 필요한 기록 링크를 남긴다. 처리 결과가 없으면 해당 장을 만들지 않는다.
	- 장기적인 결정·실패 원인·구현 결과는 [DevNotes](DevNotes/README.md)에 보존한다.
	- 등록 취소·완전 삭제 요청은 본문·처리 표·앵커·관련 참조까지 제거하고 임의로 복원하지 않는다. 과거 본문은 Git 이력으로 확인한다.
	- 등록 취소를 기능의 영구 기각이나 검증 완료로 해석하지 않는다. 문서 개편 이력은 마지막 H2에서 관리한다.

## 1. 보류 과제

> **작성 안내**
>
> 새 항목에는 사용자 요청일·요청 요지를 남긴다. 과제는 문제·전략으로 작성하고 중요한 선행 조건·보류 사유를 포함한다. 확정 사항·사용자 의견·AI 제안을 구분하고 상세 구현 이력은 보존 기록으로 연결한다.
